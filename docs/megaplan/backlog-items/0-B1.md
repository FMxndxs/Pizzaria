# 0-B1: Adiciona `ready` ao enum `order_status`

## Business Outcome
O banco de dados reconhece o estado "pronto" (`ready`), permitindo que a máquina de estados distinga entre "em preparo" e "pronto para despacho/retirada".

## Scope
- Executa `ALTER TYPE order_status ADD VALUE IF NOT EXISTS 'ready' AFTER 'preparing'` no Supabase.
- Atualiza `docs/database/schema.sql` para refletir o enum com `ready`.
- **Não inclui:** migração do código TypeScript (→ 0-B2), triggers (→ 0-B4), nenhuma lógica de transição.

## Dependencies
- Nenhuma.

## Test Plan

- Verificar que queries existentes de `orders` (sem referência a `ready`) continuam funcionando.

## Acceptance Criteria

## Implementation Notes
**CRÍTICO:** `ALTER TYPE ... ADD VALUE` não pode estar na mesma transação que referencia o novo valor. Execute o statement isolado — o SQL Editor do Supabase autocommita um statement único, então basta colar apenas essa linha e rodar. Depois coloque o restante de `002_orders_extend.sql` numa segunda execução.

O arquivo de migration é `docs/database/migrations/002_orders_extend.sql`, mas o statement `ADD VALUE 'ready'` deve ser o primeiro — e isolado — nessa migration.
