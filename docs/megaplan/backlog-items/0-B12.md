# 0-B12: `NotificationProvider` + `WaLinkProvider`

## Business Outcome
O sistema pode notificar o cliente via WhatsApp através de uma abstração trocável — no MVP, gerando um link `wa.me` pré-preenchido ao `customer_phone`; no futuro, trocando para Evolution API ou Meta sem alterar o service layer.

## Scope
- Cria `src/lib/notifications/provider.ts`: interface `NotificationProvider { notifyCustomer(order, event): NotificationResult }` e tipo `NotificationResult = { kind: 'wa_link', url: string } | { kind: 'sent' }`.
- Cria `src/lib/notifications/waLink.ts`: classe `WaLinkProvider` — reusa `buildWhatsAppUrl` e `buildWhatsAppMessage` de `src/lib/utils/whatsapp.ts`; suporta eventos `order_confirmed`, `order_ready`, `order_dispatched`.
- Cria `src/lib/notifications/index.ts`: `getNotificationProvider()` factory (retorna `WaLinkProvider` por padrão; env-switchable para outros providers futuros).
- Cria `src/lib/orders/messages.ts`: strings de mensagem por evento (pode ser PT-BR ou template com placeholders).
- **Não inclui:** chamada do provider nas Server Actions (→ A-B8); integração Evolution/Meta.

## Dependencies
- Nenhuma (reusa `whatsapp.ts` existente, sem dep em outros B-items do Cycle 0).

## Test Plan
### Unit
- `WaLinkProvider.notifyCustomer(order, 'order_confirmed')` retorna `{ kind: 'wa_link', url: string }`.
- A URL contém o número de telefone do cliente (`customer_phone`) e texto pré-preenchido.
- `getNotificationProvider()` retorna instância de `WaLinkProvider`.
### Manual
- Abrir a URL gerada em um browser → direciona para `wa.me/<customer_phone>?text=...`.

## Implementation Notes
**Implementation Note (não ADR):** a escolha de `wa.me` link sobre automação (Evolution/Meta) foi feita por custo/risco zero no MVP. A interface `NotificationProvider` é exatamente o mecanismo que torna essa decisão reversível sem reescrita: trocar o provider = um `case` a mais no factory + nova classe implementando a interface.

`WaLinkProvider` retorna `{ kind: 'wa_link', url }` — o Server Action recebe esse resultado e inclui a URL na resposta para o cliente (browser), que abre o link. O operador clica "Enviar" no WhatsApp. Isso preserva a semântica "operador confirma envio" que foi acordada.

## Known Drift
`WaLinkProvider` não reutiliza `buildWhatsAppUrl` (que aponta para o número do restaurante). Em vez disso, constrói a URL diretamente para `order.customer_phone` usando `buildNotificationMessage` de `messages.ts`. A mensagem de confirmação é diferente da mensagem de pedido — esta é uma decisão de design correta, não um desvio problemático.
