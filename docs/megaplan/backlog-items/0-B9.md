# 0-B9: Helpers SQL de role + policies atualizadas

## Business Outcome
As policies de RLS e o middleware da aplicação podem verificar papéis granulares (`owner`, `operator`, `kitchen`) sem recursão, e o comportamento existente do painel admin permanece intacto.

## Scope
- Recria `is_admin()` como `SECURITY DEFINER` → `role IN ('owner', 'operator')` (backward-compatible com todas as policies existentes).
- Cria `is_owner()` → `role = 'owner'`.
- Cria `is_staff()` → `role IN ('owner', 'operator', 'kitchen')`.
- Cria `current_user_role()` → retorna o `user_role` do caller.
- Atualiza policy de SELECT em `orders`: `user_id = auth.uid() OR is_staff()` (cozinha precisa ler pedidos para o KDS).
- Mantém policies de UPDATE/DELETE em `orders` com `is_admin()` (owner+operator).
- Atualiza `docs/database/migrations/004_profiles_role.sql` e `schema.sql`.
- **Não inclui:** atualização do middleware Next.js (será feito em 0-B10 ou B-B1); RPC `advance_status_as_kitchen` (→ B-B5).

## Dependencies
- 0-B8 (coluna `profiles.role` existe)

## Test Plan
### Manual
- Como usuário `owner`: `SELECT is_admin()` retorna `true`, `is_owner()` retorna `true`.
- Como usuário `operator`: `SELECT is_admin()` retorna `true`, `is_owner()` retorna `false`.
- Como usuário `kitchen`: `SELECT is_admin()` retorna `false`, `is_staff()` retorna `true`.
- SELECT em `orders` como kitchen (autenticado) retorna linhas.
- UPDATE em `orders` como kitchen via policy retorna erro (apenas via RPC futura em B-B5).

## Acceptance Criteria
- [ ] `is_admin()` retorna `true` para owner e operator.
- [ ] `is_staff()` retorna `true` para os três papéis.
- [ ] Kitchen consegue SELECT em `orders` via RLS.
- [ ] Kitchen não consegue UPDATE direto em `orders` via RLS.
- [ ] `schema.sql` atualizado.
- [ ] Docs atualizados.

## Implementation Notes
Os helpers `SECURITY DEFINER` evitam recursão na RLS (mesma técnica do `is_admin()` atual em `schema.sql:186-192`). O padrão existente foi lido e é reutilizado.

A policy de SELECT expandida (`is_staff()`) é necessária para que o KDS (Cycle B) funcione com o cliente autenticado Realtime — sem ela, os pedidos não aparecem para o papel `kitchen`.
