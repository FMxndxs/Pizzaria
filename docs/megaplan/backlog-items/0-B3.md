# 0-B3: Tabela `order_status_history` + RLS

## Business Outcome
O banco possui uma tabela capaz de armazenar o histórico completo de transições de status de cada pedido, com isolamento correto por papel de usuário.

## Scope
- Cria a tabela `order_status_history` com colunas `id`, `order_id` (FK→orders CASCADE), `status`, `changed_at`, `changed_by` (FK→auth.users NULL).
- Cria índices: `(order_id)`, `(status, changed_at)`.
- Habilita RLS e cria políticas: SELECT para `is_staff()`; INSERT somente via trigger (`SECURITY DEFINER`).
- Adiciona grants de SELECT/INSERT para `anon` e `authenticated` espelhando `001_fix_guest_checkout_grants.sql`.
- Atualiza `docs/database/schema.sql`.
- **Não inclui:** o trigger que popula a tabela (→ 0-B4); a função `is_staff()` (→ 0-B9, mas 0-B3 pode usar um placeholder `is_admin()` existente temporariamente).

## Dependencies
- 0-B1 (enum `ready` já existe para o tipo da coluna `status`)

## Implementation Notes
Migration file: `docs/database/migrations/003_order_status_history.sql`.

A política de INSERT é restrita ao trigger — não ao anon/authenticated diretamente — para forçar que a tabela só seja populada pelo trigger SECURITY DEFINER de 0-B4. Use `WITH CHECK (false)` para INSERT via policy regular, combinado com o grant que só o trigger bypass.
