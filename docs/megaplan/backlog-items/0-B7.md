# 0-B7: Coluna `fulfillment_type` em `orders`

## Business Outcome
Cada pedido declara se é entrega (`delivery`) ou retirada no balcão (`pickup`), ramificando a máquina de estados e determinando qual ticket é impresso.

## Scope
- Cria tipo `CREATE TYPE fulfillment_type AS ENUM ('delivery', 'pickup')` (guard com `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object`).
- Adiciona coluna `orders.fulfillment_type fulfillment_type NOT NULL DEFAULT 'delivery'` (retrocompatível: todos os pedidos existentes são `delivery`).
- Adiciona índice `orders_fulfillment_idx ON orders(fulfillment_type)`.
- Atualiza `docs/database/migrations/002_orders_extend.sql` e `schema.sql`.
- Atualiza `src/types/index.ts`: adiciona `FulfillmentType = 'delivery' | 'pickup'` e `fulfillment_type` à interface `Order`.
- **Não inclui:** exposição no checkout/painel (→ A e B cycles); lógica de branching na state machine (→ 0-B11).

## Dependencies
- Nenhuma (independente do enum de status e da tabela de histórico).

## Test Plan
### Unit
- `Order` type em `src/types/index.ts` tem `fulfillment_type: FulfillmentType`.
### Manual
- `\d orders` mostra a coluna `fulfillment_type` com default `delivery`.
- Pedidos existentes têm `fulfillment_type = 'delivery'`.
